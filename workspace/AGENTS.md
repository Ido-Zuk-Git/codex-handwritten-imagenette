# AGENTS.md -- binding rules for this workspace

## Task

Write `classify.py` in this directory. It must define `predict(path: str) -> str` that returns one of the 10 Imagenette class names: tench, english_springer, cassette_player, chain_saw, church, french_horn, garbage_truck, gas_pump, golf_ball, parachute. It is scored on 2,000 unseen images of these classes.

**Target to beat: 75.45%.** That is the hidden-test accuracy of a small CNN trained from scratch on exactly the 1,000 images you can see. Chance is 10%. Your program must get there without learning.

## The one hard rule: no statistical learning

Nothing in `classify.py` may be derived from data by an automated procedure. Concretely:

- No fitting of any kind: no gradient descent, least squares, regression, clustering across images, PCA, nearest-neighbour or exemplar tables, no averages/histograms/statistics computed over training images and stored in the program, no automated search over thresholds or kernel values whose result is written into the program.
- No pretrained anything: no model or weight files, no OpenCV `dnn`, `ml`, `face` or cascade classifiers, no default people/face detectors, nothing that loads parameters from a file or a library.
- No embedded data: no base64/zlib/hex blobs, no lookup keyed on filename or hash, no numeric array pasted from any computation over images.

Everything else is allowed. You may design anything yourself: filter banks and convolution kernels of any size (typed or generated by formula), multi-stage pipelines, segmentation, geometry, morphology, frequency-domain analysis, hand-built decision logic, per-image optimisation inside `predict` (for example fitting a circle to the edge points of the one image being classified). You may compute any statistic over the training images to inform your decisions, and you may iterate with `check.py` as often as you like. The test is: **every number in the program is one you chose and can explain.** If a script picked it, it is learning.

## Program constraints

- One self-contained file, any size. Imports: `numpy`, `PIL`, `scipy`, `cv2` (OpenCV, hand-designed functionality only: filters, morphology, contours, Hough, feature descriptors such as SIFT/ORB, colour spaces; the modules and functions listed above are banned and the scorer rejects them), and the standard library.
- `predict` must not read any file other than the image passed in (open it with PIL; `cv2.imread` and other cv2 file readers are rejected by the scorer), and must not use the network, subprocesses, `eval`/`exec`, or environment variables. Enforced: the scorer copies `classify.py` alone into an empty directory and imports it there; per-image timeout 5 s.
- **Every non-trivial line must be explained by a comment**: what it computes, and why (which visual property of which classes it captures). Every numeric constant must be explained, either by its own comment or by a comment that covers the group it belongs to (for example one comment above a block of score weights saying what they balance and how you chose them). Trivial lines (imports, plain assignments, returns, loop headers) need none. A reader must be able to understand the whole classifier from the comments alone. An uncommented non-trivial line is a rule violation, not a style issue.
- Your rules must generalise. The score is on images you have never seen. A rule that fits a training photo but would not hold for a typical photo of that class is worthless.
- Do not download anything, do not read files outside this workspace, do not look for the test set.

## Data usage

- `data/train/<class>/*.JPEG`: tune your rules on these.
- `data/val/<class>/*.JPEG`: your only estimate of how you will score on the hidden test. Measure with `python3 check.py classify.py --images data/val`. Tune on train; measure on val.
- You may view as many images as you like with look.py. **Every val image you view is moved to `data/train` at that moment** (the file moves; check.py no longer counts it in val). Looking at the val images your program gets wrong is often the fastest way to find a missing rule, and then that image becomes training material. The cost is a slightly smaller val set, so each view trades a little measurement for insight; spend views on failures you do not understand.

## Tools

- `python3 look.py <image> ["question"]`: text description of an image from a separate vision model; pass a question to focus it. It is the only way to see an image.
- `python3 look.py --batch <image1> <image2> ... ["question"]`: describe several images in one call.
- `python3 check.py classify.py --images data/train` (or `--images data/val`): runs the same scorer used for final scoring, including the rule checks, and prints accuracy and any rule violations.

## Working practice

- Keep `classify.py` runnable at all times; the file on disk is what gets scored.
- Keep `NOTES.md` updated with train and val accuracy per iteration (from `check.py`), your approach, and what you tried, including what did not work.
